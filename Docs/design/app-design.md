# UI 编辑器 App 设计

## 当前能力

Windows 桌面应用，使用 Electron、React、TypeScript 和 Vite。采用中文浅色界面、原生窗口标题栏与单窗口页面切换。
当前完成工程管理、Roblox 画布与节点编辑、JSON 保存加载，以及 Luau 脚本和模拟数据运行模式；模板、AI 及 Roblox 导入导出尚未实现。节点能力与格式见 [Roblox 静态 UI 编辑](roblox-ui.md)，运行接口见 [交互脚本与接入运行时](ui-runtime.md)。

## 核心流程

启动进入 Hub，不自动进入上次工程。Hub 参考 BlockModelEditor 的浅灰背景、白色单列卡片和青绿色操作按钮，分为“上次打开”和“最近工程”。
最新记录只显示在“上次打开”，其余按最近成功打开顺序展示。卡片显示父文件夹名称、完整工程路径、Roblox 标签及上次打开时间。

创建工程仅选择父文件夹，自动创建固定名称 `UIEditorWorkspace`；不设置独立显示名称。目标已存在且有效时询问是否打开，无效时提示更换位置，不覆盖内容。
打开已有工程要求选择 `UIEditorWorkspace` 目录。每次打开都重新读取并验证元数据，成功后更新历史再进入工作台。
取消对话框保留当前界面。文件损坏、缺失、权限或格式问题显示具体提示；失败操作不加入历史。

工作台顶部依次显示“文件”“编辑”；文件菜单提供新建界面、打开、保存、另存为和返回 Hub；编辑菜单提供撤销、重做。左侧为 Roblox 节点树，中间工作区通过“界面 / 交互脚本 / 接入脚本”切换画布和代码，右侧为选中节点属性，底部通过“资产目录 / 输出”两个页签切换内容，共用可调整的面板高度。顶部“运行 / 停止 / 重置”控制界面及脚本组合会话，具体接口见 [交互脚本与接入运行时](ui-runtime.md)。资产区左侧依次显示“永久资产”“项目资产”，默认选中项目资产，可切换选中库；项目资产入口的悬浮提示显示当前工程路径。项目资产以卡片列出工程 `interfaces` 目录内的 UI 文件，右键选择“打开”后加载界面及节点树；当前未保存界面也显示卡片和未保存标记。保存或切换界面后重新读取资产列表，重新进入工程时从磁盘恢复列表。永久资产仍为空占位，节点图片通过属性面板选择本地预览图。节点及保存操作见 [Roblox 静态 UI 编辑](roblox-ui.md)。
节点树与画布、画布与属性面板、工作区与资产目录之间的三条分隔线支持拖拽，分别调整左右面板宽度和底部资产区高度；聚焦分隔线后也可用对应方向键调整。尺寸限制保留面板和画布的可用空间，缩小窗口时自动收敛；资产库目录宽度随节点树对齐。
返回 Hub 重新加载历史和工程可用状态；不可用工程可以移出历史，但不能直接进入。移出历史不修改工程文件。

## 撤销与重做接入

参考 BlockModelEditor 的命令模式，`Editor/src/history/CommandHistory.ts` 提供通用 `EditorCommand<State>` 和 `CommandHistory<State>`。命令包含操作名称、同步的 `execute(state)` 与 `undo(state)`；返回新状态，不修改输入状态。没有实际变化时返回原引用，不入历史，也不清空重做。命令自行保存撤销所需的旧值，并保护这些值不被后续修改。

新命令成功后清空重做分支；撤销按逆序执行，重做按原顺序执行。抛错时历史栈保持不变，错误由调用方处理。一次需要整体撤销的操作应由一个命令完成。

React 通过 `useEditorHistory(initialState)` 获取 `state`、`execute`、`undo`、`redo`、可用状态与操作名称；节点操作通过此入口更新文档。`clear()` 保留状态但清空双栈，`reset(state)` 替换状态并清空双栈，用于文档加载。历史仅保存在工作台会话内，返回 Hub 或切换工程后重新创建，不写入工程文件。当前状态为静态 UI 文档，格式见 [Roblox 静态 UI 编辑](roblox-ui.md)。

工作台通过 `useHistoryShortcuts` 接入 Ctrl/Cmd+Z 撤销、Ctrl/Cmd+Y 或 Ctrl/Cmd+Shift+Z 重做。输入框、文本域、选择控件和可编辑文本保留原生键盘行为；已处理、输入法组合和重复按键不触发历史操作。面板尺寸和资产库选择仍属于工作台显示状态，不进入文档历史。历史框架不负责保存或脏状态判断。

## 文件与数据

`UIEditorWorkspace/project.json` 仅含：

| 字段 | 约束 |
| --- | --- |
| `version` | 当前固定为 `1`；不支持的版本拒绝加载 |
| `id` | 创建时生成 UUID v4，重新打开与移动目录后保持不变 |
| `mode` | 当前固定为 `roblox`，不提供切换 |
| `createdAt` | 创建时保存 ISO 时间戳 |

工程元数据不包含节点或业务数据；界面另存为 `.rbxui.json`。创建工程目录和元数据采用非覆盖操作；失败时仅清理本次创建的文件及空目录。
工程不依赖最近列表，可独立移动后重新打开。

仓库根目录保留启动批处理与说明；`Editor/` 集中源码、依赖、开发脚本、测试和构建产物；`Docs/design/` 保存设计文档。
`ToolRuntime/UIEditor-win32-x64/` 保存打包应用；开发模式与打包应用均使用根目录的 `ToolRuntime/Runtime/` 保存历史、Electron 用户数据、会话、日志和缓存。
`Runtime/recent-projects.json` 保存路径及最近打开时间，Windows 路径去重忽略大小写。名称和可用状态读取时计算，不写入工程。
自动化测试可通过 UI_EDITOR_USER_DATA 将开发版或打包版的运行数据指向隔离目录，避免改写用户历史；未设置时使用上述默认路径。
历史使用临时文件加重命名保存，损坏记录报错而非覆盖；记录写入失败时告知用户，仍允许打开有效工程。
重新打包只替换应用目录，保留 Runtime；Run.bat 启动现有构建，BuildAndRun.bat 安装锁定依赖并构建后启动。

## 模块与安全边界

React 负责 Hub 和工作台显示；主进程负责系统对话框、文件校验和最近记录。preload 暴露受限工程接口和界面新建、打开、保存、图片选择、未保存提示及窗口关闭协调接口；不暴露通用文件系统。
运行模式通过受限 IPC 由主进程管理独立 Luau 辅助程序；React 接收经过属性与结构校验的运行副本，脚本没有 Electron、Node、文件系统或网络接口。停止、窗口关闭和渲染进程退出会清理会话。交互与测试接入源码属于文档历史，临时配置和状态由接入类维护；运行结果与日志不进入历史。
新路径只来自主进程目录选择器；渲染进程提交的历史路径必须已经登记。主进程校验 IPC 来源，仅接受本地应用主框架。
渲染进程关闭 Node 集成，启用上下文隔离与沙箱，阻止外部导航和新窗口。
操作期间禁用相关按钮，主进程串行处理工程请求；同一运行目录仅允许一个应用实例。

## 取舍与验证边界

Electron 与 TypeScript 用于尽快交付桌面工程管理；本轮接受 Electron 运行时体积，不引入 Rust 构建链。
ToolRuntime 延续用户参考工程的本地运行方式，需要应用所在目录可写。不增加安装器、签名或自动更新。
仅支持 Roblox 模式。已有静态节点的 Studio 显示对比测试；App 冒烟测试不能代替
Studio 或设备验收，测试覆盖和已知差异见 [显示对比测试记录](../../Editor/tests/roblox-display-report.md)。
