# 图片资产与 Roblox 映射

## 工作区

底部提供“UI 资产 / 图片资产 / 输出”。UI 资产只列“永久UI / 项目UI”，图片资产只列“永久图片 / 项目图片”，分别记住当前库。永久UI沿用空占位，项目UI沿用工程界面文件列表。

图片列表直接显示当前库的卡片，提供“导入本地图片”按钮，使用系统文件选择器导入到当前选中的永久或项目图片库；不会上传 Roblox，资源 ID 初始为空。导入成功后刷新列表并选中新资产，不自动创建或修改节点；取消不修改资产库，失败显示具体错误，运行或处理操作时禁用导入。不提供搜索栏或本地文件拖入导入。每张卡片使用统一的 124×76 矩形预览框，图片保持比例完整显示，不撑开预览框；卡片显示名称和“仅本地 / 已配置 ID”。点击图片即在工作台现有右侧属性面板展示图片属性；点击节点树或画布节点切回节点属性，底部不另建属性表单。节点的“定位图片资产”切到图片页并选中对应图片。图片可应用到当前节点或插入新 ImageLabel；拖入画布在 ScreenGui 下创建图片节点。

图片属性提供预览、名称、标签和唯一 Roblox 资源 ID。永久与项目图片使用相同字段，不提供默认/覆盖配置。接受正整数字符串或 `rbxassetid://…`，存储统一为完整引用。未保存属性切换页签、库、图片或节点时提示放弃修改。属性点击保存即落盘，不进入界面撤销历史；应用和插入图片节点进入文档历史。

图片列表不显示常驻操作按钮。资产卡片右键弹出菜单，提供「应用到选中节点」「插入图片节点」「打开目录」「复制 ID」。菜单在点击外部、按 Escape、滚动或切换库时关闭。「打开目录」通过系统文件管理器打开图片所在目录：永久图片为 `SharedAssets/image-assets`，Roblox 项目图片为 `ArtSource/UI` 下原图所在目录；内置图片属于永久库。永久图片以 Data URL 保存于清单，项目图片直接保存原始文件。「复制 ID」复制完整 `rbxassetid://…` 引用；未配置 ID 时禁用。

项目图片按目录浏览，文件夹卡片双击进入，“返回上级”回到父目录；空白处右键“新建文件夹…”在当前目录创建真实文件夹，支持逐层创建子目录。项目图片右键“移动到文件夹…”可选择根目录或已有文件夹，移动后进入目标目录；原图和 `.meta` 一起移动，保留资产 ID、标签和上传历史，目标同名时拒绝覆盖。文件夹及图片位置直接来自 `ArtSource/UI`，不另存目录清单。工程打开期间递归监听该目录，外部新增、修改、移动、删除原图或 `.meta` 后自动刷新图片预览、资产信息与文件夹列表；目录尚未创建或删除后重建也能继续监听。当前浏览目录被删除后返回图片根目录。导入及烘焙仍保存到项目图片根目录，导入后回到根目录并选中图片。

项目图片右键“删除图片…”或选中图片按 Delete，均弹出二次确认，默认取消；取消不删除文件，确认后删除原图及 `.meta`，不删除文件夹或云端 Roblox 资源。资产目录操作立即落盘，不进入界面撤销历史；引用图片的 UI 节点保留 ID、Image 和预览快照，资产缺失沿用既有反馈。图片属性输入框中的 Delete 保持文本编辑行为；删除图片及随后再次按 Delete 不会误删当前 UI 节点。永久图片不提供这些目录、移动或删除操作。

## 节点烘焙

节点行右键“烘焙为图片…”打开弹窗，设置图片名称、宽高像素和转换类型 ImageButton / ImageLabel。按钮默认转换为 ImageButton，其他可显示节点默认 ImageLabel；根节点和辅助组件不能烘焙。默认分辨率为当前布局计算后的节点本地尺寸（四舍五入，至少 1 像素），不受画布缩放影响；每边支持 1–4096 整数像素。指定不同分辨率只改变图片精度，不改变节点布局大小。

使用同一 DocumentPreview 渲染器在隔离的透明 Electron 窗口中计算完整文档布局，然后提取目标节点及子树，按指定分辨率缩放渲染为 PNG，不包含编辑器选中框、背景、父节点或兄弟节点。目标节点的外圈描边计入捕获范围，连同节点内容适配到指定图片宽高，保留圆角及其外部透明像素；转换节点的位置与尺寸不变，描边占用图片内的一部分空间。超出节点及其描边范围的溢出子节点仍被裁切；不可见或零尺寸节点报错。自身旋转和 UIScale 留在替换节点上，不重复烘焙；子节点的旋转和缩放成为图片内容。烘焙不执行交互和接入脚本。

烘焙包含右键选中节点自身的底色、图片和其他外观，不仅是其子节点。例如选中关闭按钮的纯色图片节点时，该底色图片与叉号子节点合成为同一张 PNG，并在原节点位置替换为图片按钮或图片节点。

PNG 通过项目图片导入流程保存到同级 `ArtSource/UI`，生成 Toolkit `.meta`，同名追加数字而不覆盖。图片资产立即保存，Roblox ID 初始为空；使用已有图片属性“上传到 Roblox”接入上传。超过单张 8 MiB 时烘焙失败，不替换节点。

转换保留节点 ID、名称、位置、尺寸、锚点、旋转、可见性、层级及布局顺序，并保留 UIScale、UISizeConstraint、UIAspectRatioConstraint。其他子节点和外观属性合成到图片中，替换节点使用透明背景、白色图片着色和 Stretch，引用生成的项目图片资产。整次节点转换进入一条撤销命令，撤销完整恢复原子树；撤销不删除已经生成的图片资产。引用被合成子节点的脚本需要相应调整，编辑器不自动重写脚本。

## 数据和解析

资产使用稳定内部字符串 ID，平台当前固定 Roblox。永久图片继续保存于 UIEditor 仓库根目录 `SharedAssets/image-assets/catalog.json`，兼容 version=1/2；不改变永久库的共享与迁移规则。

Roblox 工程的项目图片直接递归读取 `UIEditorWorkspace` 同级 `ArtSource/UI`，与 Toolkit 共用原图及完整文件名追加 `.meta` 的 JSON 元数据，不再读取或写入项目 `image-assets/catalog.json`。导入保存原图及 meta，同名文件追加数字，不覆盖；目录内直接放入的受支持图片首次读取时生成 meta。保留 PNG/JPEG/WebP/GIF、单张 8 MiB、项目库 100 张/64 MiB 限制，拒绝链接及损坏 meta。

meta 完全沿用 Toolkit 的 `schemaVersion=1`、32 位十六进制 `id`、`kind=Image`、`tags` 数组及 `uploads` 历史，不添加 `uiEditor` 或编辑器专用字段。图片引用直接使用 meta.id，名称来自原图文件名；改名同时移动原图与 meta，拒绝覆盖同名文件。项目图片用途为普通图片，平铺等效果由节点属性维护。标签与 Toolkit 一致，以逗号分隔，保存为去重数组，保留标签内部空格；不会自动打标签。

PNG 按同级 `GameKitWorkspace/setting.json` 的所有者及当前原图 SHA-256 匹配上传记录，后续 Toolkit 写入的新结果在重新读取时可见。配置 ID 写入同一 uploads 格式，需要已配置所有者；清空 ID 会移除该所有者与当前内容匹配的记录。未知字段和不匹配的旧上传记录保留。非 PNG 的 Toolkit 上传哈希对应转换后的 PNG，当前编辑器不能自动匹配此类记录，也不另存专用 ID；此类图片的云记录由 Toolkit 维护。

项目图片与 meta 一起提交 Git，移动时应移动整个工程父目录，保留 `UIEditorWorkspace / ArtSource / GameKitWorkspace` 的同级关系。应用不包含旧项目图片清单迁移逻辑；已有工程需一次性迁移，将 UI 图片引用同步为 meta.id。编辑器界面及文档快照仍使用 Data URL，不将本机文件路径写入界面定义。

永久图片的内容、稳定 ID、名称、标签和 Roblox ID 保存在同一清单，不能只提交 UI 文件或程序代码而漏掉图片清单。电脑 A 上传成功并提交清单后，电脑 B 拉取并重新打开编辑器即可读取相同图片和资源 ID，不需要再次上传。共享清单不包含 API Key、本机路径、Toolkit 令牌或任务状态；未取得成功 ID 的上传任务不会跨电脑恢复。

开发版与默认 `ToolRuntime/UIEditor-win32-x64/` 打包版均使用仓库根目录的同一 `SharedAssets`，不复制进 app.asar 或打包资源，不被重新打包覆盖；分发或移动打包版时需保留这一相对目录结构。设置 `UI_EDITOR_USER_DATA` 的隔离测试使用该 Runtime 的同级 `SharedAssets`，不会改写真实共享库。

首次访问共享库时兼容迁移旧 Runtime 的永久图片，仅添加共享清单尚不存在的资产 ID，共享清单已有内容和 Roblox ID 优先；不能用电脑 B 的旧本机 ID 覆盖 Git 拉取的 ID。迁移后保留旧清单，并在旧 `Runtime/image-assets/shared-library-migrated.json` 写本机标记，后续不重复导入旧记录。损坏清单明确报错，不覆盖损坏内容；内置默认数据继续作为未配置资产的回退。

同一主进程内，所有资产存储实例按规范化清单目录共享串行队列，迁移、导入和修改在队列内重新读取并写入，异常也释放队列；不能让并发 MCP 读取触发的旧迁移快照覆盖刚保存的资源 ID。此队列不协调外部 Git 操作或其他进程。

图片节点仅保存可选 `imageAssetId` 与已解析的 Roblox `Image`，不支持节点 `previewImage`，加载与制作边界拒绝该旧字段，不提供存档升级。图片数据只属于图片库。编辑器、保存、运行及 MCP 均取图片自身的 robloxId；永久图片的 ID 在项目间共享，项目图片只属于自己的工程。画布优先使用与当前 Image 一致的资产引用，否则按 Image 资源 ID 查找本地图片；运行脚本切换 Image 时随之切换预览。缺失资产时保留已保存 Image，找不到本地图片则显示缺图提示，不影响有效资源 ID 的导出。库存在但未配置 ID 时只能本地预览，导出需先配置 ID。

引用节点的 Image 属性只读，应选中图片资产修改资源 ID，或先解除引用再手动设置。平铺、颜色、透明度和尺寸由节点维护，配置 ID 不重置这些属性。图片引用仍使用文档 version=3 的可选节点字段；无引用节点可手动设置 Image；预览按资源 ID 从图片库查找，不提供节点本地预览图片入口。

## AI 与验证边界

`uie.assets.search` 查询名称、标签、库并分页，返回 robloxId；`uie.assets.get` 返回详情与图片预览；`uie.assets.configure` 保存名称、标签和唯一 robloxId，省略字段保留原值，不支持 projectRobloxId 参数。`uie.assets.import` 接收当前 sessionId/revision、library（project/permanent）和本地图片绝对路径 filePath，由主进程读取并校验 PNG/JPEG/WebP/GIF、单张 8 MiB 上限及普通文件类型；不接受跨工程写入、远程链接或嵌入数据，不上传。无需打开界面即可导入，运行时禁止；成功立即保存资产库并返回无图片数据的资产摘要和新会话，不进入文档历史。先查询并复用已有资产，缺少时导入，再重读状态，通过 `ui.assets.apply(nodeId, assetId)` 应用到节点，随 code.execute 整笔支持撤销、dry-run 与失败回滚。不再提供 previewImage 创建选项或 setPreviewImage API。制作 VM 不开放文件与网络。资产导入和属性变化使旧 MCP 编辑会话失效，需重新读取状态。

图片属性提供「上传到 Roblox」；已有 ID 时按钮明确标注「替换 ID」，未保存配置须先保存。点击后由主进程读取资产内容，使用 Toolkit 已配置的资源所有者与 API Key 上传，不在 UIEditor 管理云端凭据。导入 Roblox 前也会列出未配置 ID 的图片，支持单张或逐张批量上传，详见 [Roblox 一次性导入](roblox-import.md)。通过 `/discover.uiEditorImageUpload === 1` 检查能力，旧版提示更新并重启，不影响原有 UI 导入。

主进程取当前 `UIEditorWorkspace` 同级 `GameKitWorkspace` 的真实路径，按 Toolkit 的路径规范化 SHA-256 前 16 位工程 ID 匹配已运行且有 PlaceId 的工程；Windows 忽略路径大小写。明确匹配时直接上传，不要求选择工程；找不到匹配时才显示工程选择，不因只有一个其他工程或名称相同而自动上传。

UIEditor 启动时即由主进程连接 Toolkit，无需打开工程或上传弹窗；失败时每隔 5 秒重连，连接恢复后停止重试，详见 [Toolkit 连接生命周期](roblox-import.md)。重连只刷新工程与令牌，不自动提交图片或重试失败任务；上传弹窗的原目标工程与任务保持不变，可刷新连接、重试上传或继续查询。关闭弹窗不停止应用级连接重试，退出编辑器才清理连接定时器。

单张源图片与转换后的 PNG 上限均为 8 MiB；Toolkit 校验宽高小于 8000、总像素不超过 16777216，非静态 PNG 转换为 PNG，动画只取第一帧。上传使用 `/ui-editor/image-upload`，查询使用 `/ui-editor/image-upload-task`；按返回的 `pollAfterMs`（至少 3 秒）串行查询，区分处理中、等待审核、成功与失败。成功的合法 Image 引用自动回填并保存，配置保存失败可单独重试保存 ID；失败不改原 ID，连接错误可继续查询。关闭对话框停止 App 查询，不取消已提交的 Toolkit 操作，再次提交同一图片复用缓存；没有资产选择触发的后台自动上传。

无游戏权限查询。通过 Toolkit 导入 UI 时使用解析后的资源 ID，见 [导入设计](roblox-import.md)。本地预览、ID 语法正确、配置保存与上传审核通过均不能证明目标游戏有权加载；配置页明确显示权限未验证。

上传成功和重试保存仅提交资产 ID 与 Roblox ID；主进程在清单队列内读取最新记录，仅更新 Roblox ID，保留等待审核期间通过 MCP 保存的名称、标签和图片内容，不回写上传开始时的配置快照。

## 检查

`npm run test:bake` 验证布局分辨率、转换和撤销，并运行隔离 Electron 冒烟检查选中图片节点自身与叉号的合成像素、四边外圈描边、圆角透明像素、指定分辨率、项目原图和 meta、保存重开，以及嵌套文件夹、移动、删除确认与取消、Delete 不误删 UI 节点。`tests/image-assets.test.ts` 检查目录遍历拒绝、移动保留元数据、同名冲突和原图/meta 成对删除。不实际上传 Roblox。

`npm run test:image-upload` 构建并运行隔离的 Electron 启动测试，验证 Hub 阶段无上传弹窗也会连接、工具后启动时按 5 秒重试、恢复后停止且不自动上传；`tests/toolkit.test.ts` 验证连续失败、空工程列表、请求合并、退出清理和断线后令牌刷新。使用 mock Toolkit，不实际上传 Roblox。

`tests/image-assets.test.ts` 检查单一 ID、跨电脑共享、开发与打包路径一致、旧 Runtime 迁移与共享 ID 优先、项目隔离、旧清单兼容、导入、项目移动、非法 ID、损坏清单、快照与制作应用；`tests/image-upload.test.ts` 检查同级工程匹配、能力检查、通信校验与 8 MiB 边界；`npm run test:assets` 构建并运行图片资产 Electron 冒烟，验证页签分类、无搜索与导入入口、统一矩形预览、共用属性面板、配置、保存重开、画布拖入、MCP，以及 mock 上传的自动匹配、选择回退、审核等待、ID 落盘和失败保留。截图保存在忽略的 test-results 目录，不实际上传 Roblox，不能代替 Studio 验证。
