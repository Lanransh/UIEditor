# 模板风格与项目 AI 工作区

## 目标与边界

用户以二级文件夹维护整套风格：可编辑模板、详细设计规范、AI 工作入口、
资源与专项技能。项目创建时复制整套制作包，之后 AI 根据界面用途、内容规模
和按钮语义自行选择模板，不要求每次指定参考。
不提供在线市场、同步服务或复杂风格编辑器；不内置 AI 模型。

## 风格库与路径

- 开发版：仓库根目录 `TemplateStyles/`。
- 打包资源：`UIEditor-win32-x64/resources/TemplateStyles/` 是分发种子。
- 打包可编辑库：应用目录的父目录 `TemplateStyles/`，默认
  `ToolRuntime/TemplateStyles/`，位于 packager 替换范围之外。
- 第一次发现只补充完全不存在的风格文件夹，先写隐藏临时目录再发布；
  已有同名风格整套跳过，包括损坏或用户修改的目录。
  重新打包、启动和再次发现不合并、不覆盖、不清空用户风格。
- 运行数据重定向 `UI_EDITOR_USER_DATA` 不改变风格库位置。

文件夹名作为风格 ID 和显示名称；说明取 `Game-DESIGN.md` 首个非空、
非标题行，不增加固定样式配置。每套风格的文件/节点名称自由，
实际文件和规范负责用途映射，程序不硬编码窗口与按钮名。

当前种子 **多彩棋格风格** 从实际 UIEditor 模板取得，保留 7 份独立模板：
SmallWindow、MediumWindow、LargeWindow、Title、CloseButton、
OperationButtonExamples、ProgressBar。不包含用户要求删除的
TemplatePage 展示页；没有修改来源工程原件。
采用鲜明的多彩游戏配色，标题默认红色，可按主题选择红、橙、黄、绿、
蓝、青、紫或粉色，不固定红色。按钮保留原有语义色，
标题、按钮和进度使用白字描边；黑色窗口底板与 Stud 平铺纹理保留，
“棋格”不表示改用棋盘格贴图。模板不包含全画布展示背景。
配色与节点结构以实际模板及制作规范为依据。

## 制作包协议

必需：非空 `AGENTS.md`、`Game-DESIGN.md`、
`template-references/**/*.rbxui.json`（至少一份，沿用当前文档校验）。
可选：根目录其他 Markdown、`assets/`、`references/`、
`.agents/skills/`。这些目录保留所有必要文件及子目录结构；
不强制创建空 assets 或 skills。
只有约定范围会复制，不复制无关顶层文件或运行目录。
选定目录内的 node_modules、Git、缓存、构建输出、日志与临时文件排除。
链接、目录联接与特殊文件拒绝，不跟随到项目外。

文档按复制后的布局组织相对引用，不批量替换用户内容：

```text
UIEditorWorkspace/
├─ project.json
├─ interfaces/
├─ template-references/
│  └─ 风格实际模板及子目录
└─ AgentWorkspace/
   ├─ AGENTS.md
   ├─ Game-DESIGN.md
   ├─ 其他必要 Markdown
   ├─ assets/             # 有资源时才存在
   ├─ references/         # 有补充说明时才存在
   └─ .agents/skills/     # 有专项技能时才存在
```

根提示词/规范到模板使用 `../template-references/...`，到规范使用
`Game-DESIGN.md`，到资源/skills 使用当前工作区相对路径。
本地 Markdown 链接在投影后的项目内检查闭合，拒绝绝对本机链接、
越界和遗漏资源；HTTP 链接是补充资料，不由 App 下载或复制。
普通 Markdown 链接可使用 URL 编码、尖括号和可选引号标题。
必要知识和资源应包含在包中，不能仅链接到网络资料。

图片预览保存在模板 JSON 中，Roblox ID 独立保存；不允许通过 imageAssetId
关联来源工程或全局图片目录，以免后续被来源图片变化覆盖。
需要从项目图片库制作模板时，保存为含 previewImage 与 Image 的独立快照。
原始模板、提示词及资源按字节复制，不重写元数据、文档、类名或设计属性。
源码类的适配由项目 AI 制作新界面时处理，不修改模板原件。

## 新建、校验与失败

### Hub 画风查看

Hub 的“画风库”打开独立只读查看窗口：左侧列出真实封面、名称、数量和说明，
中间按模板相对路径列出全部模板，右侧复用 `DocumentPreview` 展示所选模板。
预览按可见顶层组件的合并范围聚焦，保留周围留白；支持适应窗口及 25%–400%
缩放，小型关闭按钮不再缩在整张空画布中。无可见组件时回退完整画布。
只读预览不选择或拖动节点、不执行脚本、不保存模板，不创建工程和历史记录。

打开及“刷新”重新发现画风并读取磁盘，保留仍存在的画风和模板选择。
模板读取仅接受画风 ID，主进程沿用包、链接、文件格式和资源引用校验，
不接受渲染进程提供任意绝对路径。空库、损坏和读取失败明确展示，可刷新重试。
底部标注“应用画风库”和实际风格目录；开发版和打包版沿用本页既定路径，
不为查看临时改用另一个库。已有工程使用独立副本，不自动同步或覆盖。

### 新建工程

新建始终先显示选择步骤；可选空白工程、整套风格，
风格选项左侧显示真实模板的静态缩略图，沿用 UI 资产的预览渲染，
右侧保留名称和说明。封面取设计规范中首先链接的模板；
没有模板链接时按模板相对路径排序取首个，不固定任何风格的模板名。
预览不执行脚本、不修改模板；不可用风格显示占位并保持禁选。
有历史时可选兼容的历史模板克隆。单选来源互斥，
主进程只接受单个风格 ID 或已登记的历史路径，
不接受渲染进程提供任意来源绝对路径或两种混合来源。

对话框显示风格描述、模板数量及缺失文档/坏模板/访问错误；
坏风格保留可见但禁选。库读取错误明确展示，仍可创建空白工程。
历史克隆仍只复制模板，不补上默认 AI 提示词来冒充完整风格。

选择父文件夹后独占创建工程目录。有效目标已存在时仅询问打开；
无效目标提示更换位置，不改已有模板、规范或 AgentWorkspace。
新建时重新读取和校验来源，先取得完整快照再复制；
文件使用独占创建。失败仅清理本次创建的文件及空目录，不递归删除用户内容。
清理受权限等阻碍时报告具体未清理路径，不谎称成功回滚。

工程内容不依赖全局库，项目移动后仍能使用相对引用；
修改项目不回写风格库，修改库不更新已建工程。
打开/重开不生成默认提示词，不覆盖用户定制文档。
project.json 保持既有版本和字段，不保存源工程本机路径。

## 项目 AI 工作入口

AgentWorkspace/AGENTS.md 是独立入口，要求先读 Game-DESIGN，
实际只读查看相关模板结构及属性，再按用途自动选择；
制作、交互测试、截图、保存重开通过 `ui-editor` MCP 完成。
模板目录目前没有专用 MCP 查询接口，由只读文件工具查看；
document MCP 仍仅访问 interfaces，图片 MCP 不冒充 UI 模板查询。

规范包含窗口档位、标题与关闭结构、按钮语义映射、各类字体/字号/
加粗/颜色/对齐/描边、布局、纹理、层级、进度、允许修改与必须保留。
可使用必要 Luau 制作/交互/模拟接入代码；
不继承 Figma 的纯文件交付、禁止代码、三类节点或专属自检限制。
来源示例不替代项目实际规则。模板原件保护与业务安全写在项目入口中。

UIEditor 模拟状态及动作不能作为真实资格校验、支付或发奖依据；
App 检查不证明 Studio/设备显示或真实业务正确。

## 验证

`tests/template-styles.test.ts` 覆盖发现、损坏、访问受限、完整原样复制、
独立性、移动、已有目标保护、相对引用、链接拒绝、复制失败回滚、
开发/打包路径及种子不覆盖。
`npm run test:styles` 构建后运行相关单元测试、真实风格选择与历史克隆冒烟；
`npm run test:styles:packaged` 验证已打包应用的同一流程。
可使用 UI_EDITOR_PACKAGE_OUTPUT/ UI_EDITOR_PACKAGED_EXECUTABLE 隔离打包验证，
不替换正在运行的用户应用。
