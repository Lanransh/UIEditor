# 制作与自检

先读 [项目入口](../../../AGENTS.md) 和 [设计规范](../../../Game-DESIGN.md)。
本技能随项目复制，不依赖全局工作区、源游戏工程或 Figma。

## 模板复用

1. 根据需求选窗口档位；从项目根 template-references 只读读取相关 JSON。
   区分文件名、document.name、ScreenGui 名和具体子节点。
2. 记录所需子树的名称、类型、父子关系、Position/Size、AnchorPoint、
   ZIndex、裁切、字体、颜色、描边、圆角、纹理及嵌入预览。
3. 用当前 `uie.editor.get_capabilities` 核对支持属性；
   用 `uie.code.execute`、`ui.nodes.create` 创建新节点和新 ID。
   制作 VM 不能读文件；模板只读发生在 VM 外，不直接改工程 JSON。
4. 保留必要子树，跳过展示背景和说明；窗口已有标题/关闭不重复加。
   禁止添加 `BackgroundImg` 或改名后的同类全画布展示背景，不为预览补白色底板。
   同父名称唯一、PascalCase；按钮 Btn、文字 Txt、可见表面 Img、
   透明容器 Box，辅助组件使用清楚的类型名。
5. Luau 交互/模拟接入只负责数据和动作，不靠运行时生成设计视觉。
   获取实际 ScreenGui 后用 FX.Loader:Here 及点分隔路径找节点；
   不复制源模板旧脚本类名或无关业务。

## 修改后必须复检

- `uie.nodes.find/get`：关键组件完整，实际点击节点类型正确；
  字号/Font 与本项目规范匹配，普通文字可编辑且不小于 16px。
- 展示背景：没有 `BackgroundImg`，也没有改名后覆盖全画布的同类背景；
  窗口、标题和按钮自身的底板正常保留，不误删组件视觉。
- 样式：逐项核对已读模板，标题默认红色，也可按主题选择规范内其他鲜明颜色，
  同步压边色；关闭绿色、主动作亮绿、付费紫色、取消灰绿、卸载橙红。
  标题、按钮和进度保留白字与文字描边、黑色外轮廓和 Stud 平铺。
  项目实际模板修改后不强套旧参数，明确差异。
- 图片：预览保存在节点中，Image 是独立 Roblox ID；不依赖本机路径，
  不遗漏资源，不逐个创建 Stud 凸点，普通文本不转图片。
- 层级：组件底板/纹理/高光压边/文本依次呈现，文字不被遮挡；
  几何与 ZIndex 以模板为准，不新增外投影、发光或模糊。
- 裁剪：按设计规范“裁剪与缩放亮缝”核对；无隐藏溢出内容需求的贴边
  装饰按钮使用 `ClipsDescendants=false`，并检查装饰和文字没有越界遮挡。
  不把 UICorner 当作子节点圆角裁剪，不一律关闭列表或滚动容器的裁剪。
  Studio 可用且本次允许验证时，检查原始比例及“适应窗口”的亮缝、边角和文字；
  未执行时明确标注，不能用 App 截图代替 Roblox 验证。
- `uie.runtime.control`、`uie.runtime.click`：运行、点击主操作和关闭，
  需求涉及时验证禁用/可用/完成、reset/stop 和模拟数据刷新。
  操作使用稳定业务 ID，动作仅改变模拟数据。
- `uie.debug.get_diagnostics`：检查实际错误；停止后修复再复测。
- `uie.debug.screenshot`：核对整体轮廓、分区、对齐、间距、
  文本、点击区与参考视觉。没有取得参考图时只称属性核对，
  不声称完成截图对比。按需求修复，不擅自改模板主题。
- `uie.document.save` 后重开：核对节点、文案、资源和脚本。
  写操作使用最新 sessionId/revision；冲突重读，脏文档不静默丢弃。

最终说明所选文件/节点、保存路径、样式保留和差异、实际执行过的检查；
未执行的 App 检查和 Studio/设备验证单独列出。
UI 模拟成功不能证明真实支付、发奖或资格校验，也不授权修改业务代码。
